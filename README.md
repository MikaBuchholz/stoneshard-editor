# Stoneshard Save Editor

Browser-based editor for Stoneshard save files. Nothing is uploaded: the page runs entirely in your browser.

## Layout

- `app/` – the web app (React, TypeScript, Vite). `app/src/codec/` decodes and re-signs save files.
- `tools/build_catalog.py` – builds the item catalog and sprites from the game's `data.win`.
- `tools/harvest_templates.py` – collects property templates for items from real save files.
- `tools/build_skills.py` – builds the skill catalog and icons from `data.win`, and the tree layouts, panel
  images and per-skill tooltips from the official wiki (needs network access).
- `tools/read_sav.py` – command-line dump of a save file, handy for inspection.
- `app/public/catalog/items.json` and `app/public/sprites/` – generated by the catalog script, committed.
- `app/public/catalog/templates.json` – generated by the harvest script, committed.
- `app/public/catalog/skills.json`, `app/public/skills/`, `app/public/trees/` – generated by the skills script, committed.
- `app/fixtures/` – one brand-new character's save, committed so the tests run in CI. See its README.

## Rebuilding the catalog after a game update

Needs Python 3 and Pillow (`pip install pillow`). Point it at the game's data file,
found via Steam → right-click Stoneshard → Manage → Browse local files:

```bash
python3 tools/build_catalog.py "/path/to/Stoneshard/data.win"
python3 tools/build_skills.py "/path/to/Stoneshard/data.win"
```

## Improving generated items

Many item details (a torch's durability, a salve's charges, a sling bullet's damage) live in the game's
object code, not its tables, so the editor copies them from real records. Point the harvest script at any
saves you have; merchant stock inside a save counts too, so a save from a well-explored character adds a lot.
Items without a template are marked "generic" in the picker.

```bash
python3 tools/harvest_templates.py path/to/character_1/save_1/data.sav path/to/another/data.sav
```

## Editing in place (optional)

By default the editor never touches your files: you download the edited save and put it in place yourself.
In Chrome and Edge an "Advanced: edit the save in place" option on the start page connects a character folder
with write access instead. Then "Save to game folder" writes the file directly, "Reload from disk" picks up
what the game wrote, and the untouched original is kept as `data.sav.original` beside the save the first
time the editor writes. Saving is refused if the file changed on disk since it was loaded. Firefox and Safari
do not offer this; the download flow is always available.

## Trying it with a real save

Put a character folder under `test/` in the same layout the game uses, for example
`test/character_1/save_2/data.sav`, or drop an extracted `character_N/` folder in the project root. Start
the dev server and drop that character folder onto the page. A save copied out of a different character
folder shows a warning and is re-signed for the folder you picked.

Git ignores `test/`, root-level `character_*/` folders and stray `.sav` files in the project root, so your
own saves stay out of the repository. The test suite does not read them either: it reads the committed
fixture in `app/fixtures/`, which is why it passes on a fresh clone and in CI.

## Assumptions that still need checking in game

- Bag positions are stored as compartment 0 plus a linear cell index on the 10-wide grid, confirmed against a
  fresh character's save (torch at cell 20 is column 0, row 2). Items whose stored cell is unusable are packed
  top-left. All of this lives in `app/src/model/inventory.ts`.
- Items added from the catalog use harvested templates where one exists, otherwise a plain shape; weapons and
  armor come from the game's item tables at base quality with full durability, verified field for field
  against real records. Containers always get their contents list; a purse without one crashes the game on load.
- Purse capacity is not enforced. The game may cap what a purse holds.

## What the editor does not touch

Container contents (backpacks, pouches, quivers), condition meters, abilities, reputation, quests, the world map,
and the `.map` files next to each save. Enchantments, curses and quality rolls above base are not generated.
Learning a skill sets its flag only: no ability points are spent and prerequisites are not checked.
Skill tooltips come from the wiki, which publishes each skill's description with its numbers already worked
out. The game's own text keeps them as placeholders like `/*Fire_Damage*/` that only resolve at runtime.

Health and energy are not editable. The save's `HP` and `MP` hold the *current* values, and the game
recomputes the maximum on load, so writing a bigger number there does nothing. The editor shows where each
maximum comes from instead: base 100 health and 60 energy (measured from a brand-new character at full),
Vitality (+4 max energy per point, +15 max health at 15/20/25/30), and each equipped item's contribution.
Skills that grant or restore these are called out but not totalled, because most of their amounts are
conditional.
Equipping follows the item tables (armor slot, weapon hands, two-handed weapons need a free off-hand,
ammo pouches and quivers go in the off-hand, backpacks on the back) but does not check attribute requirements.
